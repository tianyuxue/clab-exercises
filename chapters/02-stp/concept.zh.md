# STP/RSTP

## 场景

两台交换机之间接了**两条**线缆，用于其中一条故障时仍能连通。可就在插上第二条线缆的
瞬间，网络瘫了：链路被打满、交换机 CPU 飙升，整个过程只有几秒。

## 术语

- **环路（loop）**：帧沿着一条路径又能回到已经经过的交换机。以太网帧没有 TTL，进入
  环路就永远死不掉。
- **广播风暴（broadcast storm）**：被环路困住的广播帧。每绕一圈都会被重新泛洪、通常还
  会被复制，于是流量不断翻倍，直到链路过载、交换机 CPU 被打满。
- **STP**（生成树协议，802.1D）：让冗余链路在*物理*上保持连接，同时在其上构建一棵
  *逻辑*上无环的树。
- **根桥（root bridge）**：所有其他交换机计算路径时所参照的唯一那台交换机。
- **桥 ID（bridge ID）**：选举时交换机的身份，由 16 位**优先级**加 6 字节 MAC 组成，
  **最小**者胜出。
- **路径开销（path cost）**：到根桥距离的度量，越小路径越优。
- **端口角色**：**根端口**是网桥通往根的最优路径；**指定端口**是某网段上的最优端口；
  **阻塞**端口（RSTP 中为 alternate/backup）不转发流量，但作为备份保留。
- **RSTP**（802.1w）：现代版本，收敛从数十秒降到亚秒级。

## 为什么疼

环路里没有 TTL 能终止帧，所以一个广播就够了：它在环里循环、每圈被复制，几秒内网络就被
打垮。同一个环路还会让 MAC 表不稳定，因为每台交换机都不断看到同一个 MAC 从两个不同端口
到来。

## 为什么直觉方案不行

拔掉两条线缆中的一条能消除环路，但你就回到了单链路、没有冗余——而冗余正是你加第二条线的
目的。关闭 STP、"让两条链路都转发"只会让风暴回来，因为同一个二层网络里不能同时存在两条
活跃路径。

## 机制

STP 让两条线缆在物理上都保持 up，同时在逻辑上构建一棵**无环的树**：

1. 所有交换机选出一台**根桥**：**桥 ID 最小**的那台（先比优先级，再比 MAC）。
2. 其余每台交换机各选**一个根端口**——通往根的最低开销路径。
3. 每条网段上有一个**指定端口**负责转发，其余端口一律**阻塞**。

被阻塞的端口不承载流量，环路因此消失；但它仍在监听 STP 报文：一旦活跃路径故障，树会重新
收敛，该端口接管。这就是 STP 能同时提供**冗余**与**无环**的原因。

## 配置与查看

Linux 网桥默认不启用 STP，需要在网桥上开启：

```sh
ip link add br0 type bridge stp_state 1 && ip link set br0 up
ip link set eth1 master br0 && ip link set eth2 master br0

# 降低桥 ID 以赢得根选举（优先级是 4096 的倍数）
ip link set dev br0 type bridge priority 4096

# 查看：本机是否为根？哪些端口在转发？
cat /sys/class/net/br0/bridge/bridge_id     # 本机桥 ID
cat /sys/class/net/br0/bridge/root_id       # 与 bridge_id 相同 => 我是根
bridge -j link show                         # 每个端口状态：forwarding/blocking
```

默认定时器下首次收敛需要数十秒；实验里可用 `forward_delay`、`hello_time`、`max_age`
加快。

## 常见问题

- **默认优先级 32768**：不配置优先级时，由 **MAC 地址**决定根桥——从运维角度看结果是
  随机的。应始终在实际的根交换机上显式设置优先级。
- **阻塞 ≠ down**：被阻塞的端口链路仍是 up，随时可以接管；不要靠拔线来"修复"阻塞端口。
- **重新选举**：修改优先级会重新触发选举，会有一段收敛时间。
- **定时器**：默认定时器下首次收敛很慢；实验里已把它们调快来缩短等待。
