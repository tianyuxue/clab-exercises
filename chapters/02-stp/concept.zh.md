# STP/RSTP：为什么插上第二条线，全网反而瘫了

## 先看现场

两台交换机，中间本来只有一条线。为了链路坏掉时网络不被切成两半，你又拉了一条，两台交换机之间就有了两条路。

第二条线插上的那一刻，事情开始不对。链路灯正常，可 ping 的延迟一路往上跳，几秒后干脆不通。交换机登不上去，风扇狂转，CPU 打满。把新线拔掉，一切立刻恢复。

问题出在二层。以太网帧没有 TTL 这种“走够多少跳就丢弃”的字段。两台交换机之间只要有两条通路，一个广播帧就能在两条线之间来回打转，每转一圈还会被复制、再泛洪出去。几秒钟，带宽就被自己发出的帧吃光了。

同一条环路还会让 MAC 地址表来回翻。同一个源 MAC，一会儿从 eth1 出现，一会儿从 eth2 出现，交换机每次都得改表项，转发也跟着乱。

## 那拔掉一条不就行了？

短期可以。可你加第二条线，本来就是为了它坏的时候还有一条能用。拔掉等于把冗余一起扔了，故障照样会把网络切成两半。

那让两条线同时转发呢？更糟。同一个二层网络里只要有两条活跃路径，环路就还在，风暴只是来得晚一点。

所以问题不是“线多了”或者“线少了”，而是缺一个机制：物理上两条线都留着，逻辑上只让其中一条转发。这个机制就是 STP。

## 几个绕不开的词

- **环路（loop）**：帧从一条路走出去，又能沿另一条路回到走过的交换机。以太网帧没有 TTL，进了环路就出不来。
- **广播风暴（broadcast storm）**：困在环路里的广播帧。每绕一圈都被重新泛洪、再复制一份，流量翻着倍往上涨，直到链路和 CPU 都撑不住。
- **STP（Spanning Tree Protocol，生成树协议，802.1D）**：让冗余链路保持物理连接，同时在它们上面算出一棵逻辑上没有环的树。
- **根桥（root bridge）**：全网选出来的参照点。其他每台交换机都朝它算路。
- **桥 ID（bridge ID）**：交换机参加选举时的身份，16 位优先级在前，6 字节 MAC 在后。数值小的赢。
- **路径开销（path cost）**：到根桥要花多少代价，越小路越优。STP 用它比较两条路。
- **端口角色**：根端口（root port）是本机去根桥的最优出口；指定端口（designated port）是某段链路上负责转发的那个口；剩下的口进入阻塞（blocking），不转发业务流量。RSTP 里，这两种备份口叫 alternate / backup。
- **RSTP（802.1w）**：STP 的改进版，收敛时间从几十秒降到亚秒级。

## 根桥是谁？

STP 做的第一件事，是让所有交换机选出一个根桥。大家互相比桥 ID，最小的那台当选。

比的时候先看优先级，优先级一样才比 MAC。默认优先级是 32768，所以只要没人改过，根桥往往就是 MAC 最小的那台交换机。它是不是你规划里的核心交换机，全看运气。

实验里的三角拓扑能说明问题。`sw2` 的优先级被设成 4096，`sw1` 和 `sw3` 还是默认的 32768。谁的桥 ID 最小？`sw2`。哪怕它的位置、带宽都不适合当核心，根桥也已经是它了。

## 其他交换机往哪走？

根桥定下来，剩下每台交换机各选一个根端口。

它朝根桥的方向算路径开销，选开销最小的那个口。开销一样时，再比邻居的桥 ID 和端口号。根端口就是这台交换机去根桥的出口，所有往根桥方向去的流量都走这个口。

## 哪个口要停下来？

接下来，每段链路上留一个指定端口负责转发，其余端口阻塞。三角拓扑里，三条链路不可能都转发，总有一个口要停下来。

注意“阻塞”这个词。被阻塞的端口链路还是 up，只是不转发业务帧。它照样收邻居定期发来的 STP 报文（BPDU），知道树现在长什么样。一旦正在转发的那条路断了，交换机会重新算树，这个口很快被叫起来接管流量。

冗余和无环能同时成立，靠的就是这一点。物理上一条线都没少，逻辑上只剩一棵树。

## 动手：在 Linux 网桥上开 STP

Linux 网桥默认不开 STP，建桥的时候就得把 `stp_state` 打开：

```sh
ip link add br0 type bridge stp_state 1 && ip link set br0 up
ip link set eth1 master br0 && ip link set eth2 master br0

# 优先级以 4096 为步长，数值越小越容易当选根桥
ip link set dev br0 type bridge priority 4096
```

然后看结果：

```sh
# 本机桥 ID
cat /sys/class/net/br0/bridge/bridge_id
# 和 bridge_id 相同，就说明本机是根桥
cat /sys/class/net/br0/bridge/root_id
# 每个端口的状态：forwarding / blocking
bridge -j link show
```

`root_id` 和 `bridge_id` 一致，本机就是根。`bridge -j link show` 打出 JSON，里头每个端口有自己的 state，正在转发的显示 forwarding，被树挡住的显示 blocking。

STP 用三个定时器控制节奏。`hello_time` 决定多久发一次 BPDU，`max_age` 决定多久收不到邻居消息就认为路断了，`forward_delay` 决定端口从阻塞走到转发要等多久。默认值下，第一次收敛要几十秒。实验拓扑把这三个值调成了 `forward_delay 2`、`hello_time 1`、`max_age 4`，不用干等半分钟。

## 几个容易踩的坑

### 根桥怎么跑到边缘交换机上了？

不配优先级，根桥就由 MAC 决定，结果对运维来说基本是随机的。生产网络里，应该在规划好的核心交换机上显式设一个更小的优先级。实验里 `sw2` 的 4096 就是这么把根抢走的。

### 端口显示 blocking，是不是坏了？

不是。链路还是 up，端口在备份状态等着接管。别拔线，也别为了让它 forwarding 去关 STP。

### 改了优先级，为什么没有立刻生效？

改优先级会重新触发选举，树要重新收敛，这中间会断一小会儿。改完等收敛，别在收敛过程中反复改。

### 两条千兆线，为什么只跑出一条的带宽？

STP 只负责消环，不做负载分担。三角里总有一条链路被阻塞，带宽就闲着。想让两条线都用上，得上链路聚合（LACP），那是另一套机制。
